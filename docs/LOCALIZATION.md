# 多语言支持方案

状态：代码已实现，原生交互待实测。日期：2026-10-17。

## 产品范围

首期提供简体中文（zh-CN）与 English（en），设置入口提供“跟随系统 / 简体中文 / English”。首次启动默认跟随系统；系统语言为中文时使用简体中文，其他语言使用英文。显式选择优先，重启保留。语言名称始终显示其自身写法，便于切换回来。

切换后主窗口、已打开的浮窗和托盘同步生效，无需重启。语言只影响展示，不修改账号别名、原始观测、币种、额度含义或查询行为。首期不翻译 README 和开发文档，不增加第三种语言。

## 当前实现与改造位置

- `src/App.tsx`：导航目前以中文标题作为页面状态，先改为稳定页面 ID，再翻译导航、标题、通知与操作反馈。
- `src/components/`：覆盖连接编辑、网络、设置、历史、关于页，以及 placeholder、title、aria-label、确认和错误提示。
- `src/lib/presentation.ts`：集中处理采集状态、额度名称、提醒、相对时间；已有硬编码 zh-CN 日期格式。翻译展示文案时保留额度、余额、过期及未知状态的语义。
- `src/widget/Widget.tsx`：覆盖紧凑标签、提示、操作失败和原生右键菜单；英文长度需要实际检查。
- `src-tauri/src/lib.rs`：托盘菜单和 tooltip 在 Rust 创建，需要启动时和切换时同步语言，包括暂停/恢复、显示/隐藏的动态文案。
- `src/lib/types.ts` 与 Rust `AppSettings`：增加受约束的语言偏好，沿用后台 settings JSON 持久化与 state-changed 广播，不依赖各窗口自己的 localStorage。
- ProviderDescriptor 的 capability、limitation、setupInstructions、authorizationLabel、networkNote 等包含展示文案，须一并处理；保持 Provider 集中注册，业务页面不增加 provider_id 条件分支。

## 展示契约

前端以稳定语义 key 管理两份语言资源，支持命名参数插值，不以中文句子作 key，不拼接零散词语组成长句。语言资源应能校验 key 和插值参数一致。

后端返回的稳定错误码由展示层翻译。实现前逐项盘点直接返回字符串的校验/操作错误，将用户可见错误逐步统一成 code + params；未知错误保留可诊断信息并显示本地化通用提示，不自动机翻任意后端文本。

已知额度窗口通过稳定语义标识翻译；未知窗口保留来源名称。不能仅按 metricId 的不稳定片段猜测窗口含义。品牌名、模型名、用户别名、URL 和官方命令保持原样；渠道名称中的中文名称和说明随语言切换。历史提醒在渲染时翻译，不为语言切换重写观测记录。

日期和相对时间使用所选语言的格式，继续使用本地时区。金额保留来源十进制精度与币种，不因语言切换转换汇率或将未知币种推断为人民币/美元。

旧设置缺少语言字段时使用跟随系统；未知语言值仅回退该字段，不能导致整份设置反序列化失败或丢失其他偏好。系统语言变化由同一个解析规则处理，主窗口和浮窗不能各自得出不同语言。

## 实施顺序

1. 建立语言资源、稳定 key、插值及回退规则；增加后台语言偏好与旧设置兼容检查。
2. 接入设置入口和跨窗口同步；改造页面 ID、公共格式化和主窗口全部文案。
3. 覆盖连接说明、错误反馈、历史提醒、浮窗及 Rust 托盘；集中整理 Provider 展示资源。
4. 检查两种语言的布局、键盘操作和无障碍标签，补充 README 能力说明及实际验证证据。

## 验收标准

- 两份资源 key 与占位参数一致；缺 key 的开发检查明确失败，运行时有确定回退。
- 首次启动、显式切换、重启、旧设置及未知设置值均符合规则；其他偏好不丢失。
- 主窗口切换后，浮窗与托盘同步；关闭主窗口再从托盘操作也使用正确语言。
- 未知、过期、无权限、限流和余额未知币种两种语言均准确表达，不出现模拟值。
- 验证长英文错误、连接说明、8 账号浮窗、折叠状态及 Windows DPI 下的截断与可操作性。
- 执行前端 typecheck/lint/test/build 与相关 Rust fmt/check/clippy/test；真实 Windows 主窗口、浮窗、托盘交互另行记录，不能以浏览器预览代替。

## 实现记录

- `src/lib/locales.ts` 集中维护配对中英文资源，`i18n.ts` 提供语义 key、命名插值、语言订阅、文档 lang 和缺 key 回退；未增加依赖或改动锁文件。
- 主窗口导航使用稳定页面 ID；页面、设置、连接、网络、关于、历史、提醒和浮窗文案均接入语言资源。`providerPresentation.ts` 集中映射八个适配器的名称和展示说明，保留原始连接配置及数据库中的产品名。已有历史/提醒缺少 providerId 时，只按注册的完整名称匹配翻译，未知名称保持原样。实验性标记由集中展示规则决定，不依赖翻译后的名称前缀。
- Rust `LanguagePreference` 负责白名单与系统语言解析；Windows 使用 GetUserDefaultUILanguage。`set_language` 仅允许主窗口调用，沿用 settings JSON 和 revision 广播；托盘在后台直接更新，显示/隐藏及暂停/恢复继续使用当前语言。
- 启动和重新读取设置时解析系统 UI 语言，窗口重新获得焦点会读取设置。WebView 启动提示可暂用浏览器语言，读到后台后以后端为准；未增加跨窗口 localStorage 语言状态。
- 金额原文、币种、未知/过期、限流和重置语义保持不变，历史数据不重写。已知错误码和旧版固定校验文本在展示层翻译；未识别的诊断文本保留原文，尚未把所有后台字符串升级为结构化 code + params。
- 中文删除确认词保持原协议；英文界面要求输入 DELETE ALL DATA，通过前端确认后发送原后端确认协议。语言改变后会重新判定输入是否匹配。

运行仍使用 README 的 `pnpm tauri dev`；设置页顶部提供语言选择。只运行 `pnpm dev` 无法验证设置写入和原生菜单。

自动检查与原生验证分别记录。人工待验：语言切换与已打开浮窗同步、托盘动态动作、重启恢复、长英文错误、八账号浮窗、折叠状态、键盘操作与高 DPI。当前未启动真实账号采集验证，也未以浏览器或组件渲染冒充桌面测试。
